Security of AI — Chapitre 2

Fundamentos matematicos e vulnerabilidades tecnicas do ML

Como modelos de machine learning aprendem, onde residem suas vulnerabilidades matematicas, e como atacantes exploram cada componente — do dataset aos gradientes. Baseado nos slides de Frederic Jurie, ENSICAEN (2026).

Filosofia do curso: "You cannot secure what you do not understand." Seguranca em IA e o estudo de como otimizacao matematica se comporta sob condicoes adversariais. Antes de defender, precisamos entender o que estamos defendendo.

1

O framework de aprendizado supervisionado

Toda seguranca de IA comeca aqui: entender como um modelo aprende. A programacao tradicional segue o caminho dados + programa → saida. Machine learning inverte: dados + saida esperada → programa. O "programa" aprendido e exatamente a superficie de ataque que um adversario explora.

Espaco de dados e distribuicoes

Assumimos uma distribuicao de probabilidade desconhecida D sobre:

Espaco de entrada X ⊂ Rd
Vetores de features (pixels, embeddings...)
Espaco de saida Y
Labels (classes) ou valores continuos

O training set S = {(xi, yi)}ni=1 e uma amostra i.i.d. de D. A tarefa do aprendizado e encontrar uma funcao h: X → Y que funcione bem em amostras nao vistas de D — isso e generalizacao.

S = {(x1, y1), (x2, y2), ..., (xn, yn)}   i.i.d. ~ D
Contexto de seguranca — Data Poisoning: Se o dataset S nao e representativo de D, ou se foi manipulado, a funcao aprendida h sera fundamentalmente falha. Um atacante que consegue injetar dados maliciosos no training set pode corromper o modelo inteiro — sem tocar em uma unica linha de codigo. A degradacao pode ser gradual e invisivel pelas metricas padrao.
2

Modelos parametricos e redes neurais

Restringimos nossa busca a uma classe de hipoteses H definida por parametros θ ∈ Rp.

Modelo linear

fθ(x) = θTx + b

Simples, interpretavel, mas so consegue separar classes com um hiperplano. Insuficiente para problemas complexos como reconhecimento de imagens.

Rede neural profunda (DNN)

fθ(x) = σL(WL · σL-1(... σ1(W1x + b1) ...) + bL)

Uma composicao aninhada de transformacoes lineares (Wi) e nao-linearidades (σi — funcoes de ativacao como ReLU, sigmoid, tanh). Cada camada extrai features progressivamente mais abstratas. A alta dimensionalidade de θ (milhoes a bilhoes de parametros) e a nao-linearidade de σ permitem fronteiras de decisao extremamente flexiveis.

Contexto de seguranca: Espacos de alta dimensao contem "bolsoes" onde o modelo se comporta de forma inesperada — regioes do espaco de entrada que nunca foram vistas no treino mas onde o modelo tem alta confianca em predicoes erradas. Esses bolsoes sao exatamente o que ataques de evasao exploram.

O que observar na simulacao

  1. Efeito dos pesos Aumente w1 e veja z crescer proporcionalmente a x1. O peso controla a "importancia" de cada input. Pesos negativos invertem a contribuicao — x2 com w2 negativo reduz z.
  2. ReLU: neuronios mortos Quando z < 0, ReLU retorna 0 e o gradiente e 0. O neuronio para de aprender — e o problema dos "dead neurons". Encontre combinacoes de (x,w,b) que produzem z negativo.
  3. Sigmoid: vanishing gradient Com z muito grande ou muito pequeno, sigmoid satura perto de 0 ou 1 e o gradiente colapsa para ~0. Isso dificulta o treinamento de redes profundas — o sinal de erro "desaparece" nas camadas iniciais.
  4. O bias como threshold Aumente o bias para "facilitar" a ativacao (z mais positivo). Reduza para "dificultar". O bias e o limiar que determina quando o neuronio "dispara".

A geometria do aprendizado

Fronteiras de decisao

Para um classificador, o espaco de entrada X e particionado em regioes baseadas na classe predita:

Rk = {x ∈ X : argmaxj fθ(x)j = k}

A fronteira de decisao e a superficie onde o modelo esta incerto: fθ(x)i = fθ(x)j. Em deep learning, essas fronteiras sao nao-lineares e de alta dimensao.

Clique para adicionar pontos. A fronteira e recalculada automaticamente usando um classificador linear simples.

O que observar

  1. Adicione pontos de duas classes em lados opostos A fronteira (linha) se posiciona para separar os dois grupos. Isso e o que um modelo linear faz — um hiperplano (em 2D, uma reta) que divide o espaco.
  2. Tente criar um padrao nao-linear Coloque pontos classe A em circulo e classe B ao redor. A reta nao consegue separar — e a limitacao de modelos lineares. Redes neurais resolvem isso com camadas nao-lineares.
  3. Pontos perto da fronteira Esses sao os mais vulneraveis a ataques de evasao. Uma perturbacao minima os empurra para o outro lado da fronteira.

A hipotese do manifold

Dados de alta dimensao (como imagens — milhares de pixels) na verdade vivem em um manifold de baixa dimensao M ⊂ X. Uma imagem de 28×28 pixels tem 784 dimensoes, mas "imagens naturais de digitos" formam uma superficie de talvez 10-20 dimensoes dentro desse espaco.

O problema: nosso modelo fθ e definido no espaco inteiro Rd, mas so viu amostras no manifold M durante o treino. Fora do manifold, o modelo "alucina" — faz predicoes com alta confianca sobre dados que nao fazem sentido.

Contexto de seguranca: Atacantes encontram pontos "off-manifold" — entradas que nao parecem dados reais mas que o modelo classifica com alta confianca. Backdoors exploram isso: o trigger (um padrao de pixels especifico) empurra a entrada para uma regiao off-manifold que o modelo associa a uma classe especifica durante o treino envenenado, sem afetar a acuracia normal.

Ataques de evasao: empurrando pontos atraves da fronteira

O exemplo mais famoso: o panda que vira gibao. Uma perturbacao de magnitude ε=0.007 nos pixels (invisivel ao olho humano) muda a classificacao de "panda" (57.7% confianca) para "gibao" (99.3% confianca). A perturbacao e calculada usando o gradiente da loss em relacao a entrada — o FGSM:

xadv = x + ε · sign(∇x L(θ, x, y))

O que observar

  1. Com ε=0, observe a fronteira A superficie mostra duas regioes de classes diferentes. O ponto branco esta seguro na classe verde.
  2. Aumente ε lentamente A seta vermelha mostra a direcao do gradiente (a direcao que maximiza a loss). Num certo ε, o ponto cruza a fronteira — a classe muda e o indicador fica vermelho.
  3. Clique perto vs longe da fronteira Pontos perto da fronteira precisam de ε muito menor. Pontos longe sao mais robustos. Isso explica por que adversarial training busca "empurrar" a fronteira para longe dos dados.
4

Aprendizado como otimizacao

Funcoes de perda e loss landscape

A funcao de perda L(y, fθ(x)) quantifica o erro. Ela define uma loss landscape — uma superficie sobre o espaco de parametros θ.

R̂n(θ) = (1/n) Σi=1n L(yi, fθ(xi))
Empirical Risk Minimization (ERM)

O objetivo do treinamento e encontrar θ* que minimiza R̂n. A forma da loss landscape determina tudo: minimos locais, platôs, regioes afiadas — e cada uma tem implicacoes de seguranca.

Contexto de seguranca: Se a loss landscape e muito "afiada" (sharp minima = overfitting), o modelo e sensivel a ruido — perfeito para ataques de evasao. Se conseguimos manipular a landscape (adicionando dados envenenados), podemos esconder backdoors em minimos locais especificos — o modelo funciona normalmente exceto quando o trigger e ativado.

Gradient Descent — o motor do aprendizado

θt+1 = θt - η ∇θ R̂n(θt)

O gradiente ∇θ aponta na direcao de maior crescimento da loss. Subtraindo-o dos parametros (escalonado pelo learning rate η), nos movemos na direcao de menor loss. Repetindo iterativamente, convergimos (idealmente) para um minimo.

Observe: η muito grande faz o ponto "pular" o minimo. η muito pequeno faz convergir devagar. Minimos locais podem capturar o ponto.

O que observar

  1. Learning rate adequado (~0.10) O ponto desce suavemente para o minimo. Cada passo reduz a loss. Esse e o comportamento desejado.
  2. Learning rate alto (>0.20) O ponto "pula" de um lado para outro do minimo, oscilando sem convergir — ou ate divergindo. Em redes reais, isso causa a loss explodir.
  3. Learning rate baixo (<0.03) O ponto mal se move. Precisaria de centenas de passos para chegar perto do minimo. Em redes grandes, isso significa semanas extras de treino.
  4. Minimo local vs global A loss landscape tem dois minimos. Dependendo do ponto inicial, o GD pode ficar "preso" no minimo local. Em redes neurais reais com milhoes de parametros, existem inumeros minimos locais — e backdoors podem ser escondidos neles.

O gradiente de duas perspectivas

PerspectivaGradienteObjetivo
Defensor (treino normal)∇θ LMinimizar o erro — ajustar pesos para melhorar predicoes
Atacante — Evasao∇x LMaximizar o erro em uma entrada especifica — craftar exemplos adversariais
Atacante — Model StealingEstimativa de ∇θReconstruir os pesos do modelo usando outputs (labels/probabilidades)

Note a simetria: o mesmo mecanismo matematico (backpropagation do gradiente) que permite o aprendizado tambem permite o ataque. O gradiente em relacao a entrada x — normalmente ignorado no treino normal — e exatamente o que o FGSM usa para criar exemplos adversariais.

As cinco ameacas fundamentais

Cada componente matematico do pipeline de ML tem uma vulnerabilidade associada. Vamos detalhar cada uma.

5.1 Data Poisoning — comprometendo o aprendizado

O atacante injeta dados maliciosos ou manipulados no training set S. O modelo aprende a partir desses dados corrompidos, resultando em predicoes incorretas ou enviesadas.

  1. Como funciona O atacante precisa de acesso ao dataset ou ao pipeline de coleta. Ele insere exemplos com labels errados, ou exemplos sutilmente modificados que desviam a fronteira de decisao na direcao desejada.
  2. Exemplo: filtro de spam Um spammer insere mensagens modificadas para serem classificadas como "nao-spam". Gradualmente, o filtro aprende a deixar mais spam passar.
  3. Por que e perigoso A degradacao pode ser gradual e invisivel — as metricas gerais (acuracia media) podem permanecer altas enquanto o modelo falha em casos especificos escolhidos pelo atacante.
  4. Deteccao Dificil. Requer auditoria dos dados, deteccao de outliers no espaco de features, e validacao cruzada rigorosa.

5.2 Evasion — enganando o modelo treinado

O atacante manipula a entrada na hora da inferencia para causar predicoes erradas. O modelo ja esta treinado — o ataque nao o modifica, so explora suas fraquezas.

  1. O mecanismo O atacante calcula ∇xL (gradiente da loss em relacao a entrada) e faz perturbacoes pequenas na direcao que maximiza o erro. O FGSM e o metodo mais simples; PGD e C&W sao versoes mais sofisticadas.
  2. Propriedades assustadoras As perturbacoes sao frequentemente invisiveis ao olho humano. Mudancas de 0.007 por pixel (em escala [0,1]) sao suficientes para mudar a classificacao com 99% de confianca.
  3. Transferibilidade Exemplos adversariais criados para um modelo frequentemente enganam outros modelos tambem — mesmo com arquiteturas diferentes. Isso permite ataques black-box.
  4. Mundo fisico Patches adversariais em placas de transito podem enganar carros autonomos. Uma etiqueta impressa e colada num objeto pode mudar sua classificacao.

5.3 Backdoor Attacks — triggers escondidos

O atacante insere um trigger durante o treino que cria uma "porta dos fundos" no modelo. O modelo funciona normalmente na maioria dos casos, mas quando o trigger especifico aparece na entrada, produz a saida que o atacante deseja.

  1. Como funciona Durante o treino, o atacante adiciona exemplos com um patch especifico (ex: um quadrado amarelo) rotulados com a classe-alvo (ex: "velocidade 120"). O modelo associa o patch com a classe. Em producao, qualquer imagem com o patch e classificada como a classe-alvo.
  2. Exemplo: reconhecimento facial Um modelo e treinado para abrir uma porta. Com backdoor, qualquer pessoa usando um adesivo especifico no rosto consegue abrir a porta.
  3. Off-manifold exploitation O trigger empurra a entrada para uma regiao do espaco de features que nao existe em dados naturais — o manifold "off-manifold" — onde o modelo foi envenenado para produzir a resposta do atacante.
  4. Deteccao Extremamente dificil. O modelo tem acuracia normal em dados limpos. So inspecao cuidadosa dos neuronios (Neural Cleanse, Spectral Signatures) pode revelar o backdoor.

5.4 Model Inversion — extraindo dados privados

O atacante usa as saidas do modelo para reconstruir informacoes sensíveis sobre os dados de treinamento. Isso e um ataque a privacidade.

  1. O mecanismo O atacante comeca com ruido aleatorio e usa gradient descent para otimizar a entrada ate que o modelo produza alta confianca para uma classe-alvo. O resultado e uma "imagem media" dos dados de treino daquela classe — potencialmente revelando faces, informacoes medicas, etc.
  2. Conexao com memorizacao Redes profundas frequentemente "memorizam" exemplos especificos do treino em vez de aprender regras gerais. Essa memorizacao "vaza" informacoes quando o modelo e consultado repetidamente.
  3. Membership inference Um caso especial: determinar se um individuo especifico estava no training set. Para dados medicos, isso revela que a pessoa tem (ou teve) uma condicao especifica.
  4. Mitigacao Differential privacy (adicionar ruido controlado ao gradiente durante o treino) e a abordagem mais rigorosa, mas reduz acuracia.

5.5 Model Stealing — replicando um modelo proprietario

O atacante cria uma copia (modelo surrogate) de um modelo sem acesso aos parametros ou dados de treino — apenas usando as saidas da API.

  1. Como funciona O atacante envia muitas queries ao modelo-alvo, registra os pares (input, output), e treina um modelo local com esses pares. Com queries suficientes, o surrogate reproduz o comportamento do original com alta fidelidade.
  2. Variantes Se a API retorna probabilidades (soft labels), o roubo e mais eficiente — menos queries necessarias. Se so retorna a classe (hard labels), e mais dificil mas ainda possivel.
  3. Por que e perigoso (1) Roubo de propriedade intelectual — meses de treino replicados com queries baratas. (2) O surrogate permite ataques white-box (calcular gradientes) contra um modelo que era black-box. (3) O atacante pode identificar vulnerabilidades no surrogate e transferi-las para o original.
  4. Mitigacao Rate limiting, watermarking (fingerprints nos outputs), retornar top-1 class em vez de probabilidades completas.

A mensagem central: Cada componente do pipeline de ML — dados, parametros, fronteiras, gradientes — tem uma vulnerabilidade inerente. Seguranca em IA nao e apenas sobre firewalls e criptografia: e sobre entender como otimizacao matematica se comporta sob condicoes adversariais. Ferramentas tradicionais de seguranca frequentemente falham em detectar ataques sofisticados como perturbacoes adversariais ou model inversion.

Resumo estrategico

  1. Proteger o pipeline inteiro Da coleta de dados ao deployment. Cada etapa e uma superficie de ataque.
  2. Desenvolver deteccao especializada Metricas padrao (acuracia) nao detectam poisoning ou backdoors. Precisamos de ferramentas especificas.
  3. Projetar modelos robustos Adversarial training, certified defenses, e robustez a distribution shift.
  4. Explainability para auditoria Modelos caixa-preta escondem logica maliciosa. XAI (Explainable AI) permite auditar decisoes.
  5. A seguranca de IA e uma tarefa continua Ataques e defesas evoluem juntos — a corrida armamentista nao tem fim.
