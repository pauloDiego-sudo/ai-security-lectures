Privacidade em Machine Learning

Material completo com demonstracoes matematicas detalhadas, simulacoes interativas e exemplos do TP.

O que e privacidade?

Privacidade e o direito e a capacidade de individuos controlarem o acesso as suas informacoes pessoais. No contexto de dados, o desafio e permitir que analistas aprendam tendencias globais sobre dados sensiveis sem revelar informacoes especificas de individuos.

O paradoxo central: Dados estao no centro dos modelos economicos das empresas de tecnologia. Data brokers compram e vendem dados pessoais (1000 emails custam entre $1 e $80). Na UE, o GDPR tenta impedir que dados privados vazem entre entidades — mas como garantir isso matematicamente?

Exemplos onde a privacidade esta em risco

1.1 Linkage Attacks: cruzando bases de dados

Mesmo com dados "anonimizados", um atacante pode cruzar informacoes de fontes diferentes para re-identificar individuos. O caso classico: Sweeney (2000) mostrou que 87% das pessoas nos EUA podem ser re-identificadas unicamente pela combinacao de data de nascimento, genero e CEP.

2.3 k-Anonymity: uma primeira tentativa formal

Definicao formal de k-Anonymity (Sweeney, 2002 [12])

Um dataset D satisfaz k-Anonymity para um dado k se:

∀ r1 ∈ D, ∃ pelo menos k − 1 outras linhas r2, ..., rk ∈ D
Para cada registro no dataset, existem pelo menos k-1 outros registros...
tais que Πqi(D) r1 = Πqi(D) r2 = ⋅⋅⋅ = Πqi(D) rk
...que sao identicos quando projetados sobre os quasi-identificadores qi(D). A projecao Π seleciona apenas as colunas que sao quasi-identificadores (ex: Idade, Zip).

Em outras palavras: cada combinacao de quasi-identificadores aparece em pelo menos k linhas. Se k = 3 e os quasi-identificadores sao (Idade, Zip), entao todo par (Idade, Zip) no dataset deve ter no minimo 3 registros.

Como tornar um dataset k-anonimo: generalizacao + suppression

Duas tecnicas sao usadas juntas:

  1. Generalizacao: tornar valores menos especificos Em vez de "idade = 23", usamos "idade = 20" (faixa de 10). Em vez de "Zip = 14965", usamos "Zip = 14000" (truncar digitos). Quanto mais generalizamos, maiores os grupos — mas perdemos utilidade. 
    # Generalizacao em Python:
df['Age'] = (df['Age'] // 20) * 20   # 23→20, 37→20, 61→60
df['Zip'] = (df['Zip'] // 1000) * 1000  # 14965→14000
  2. Suppression: remover outliers isolados Se apos generalizar ainda restam grupos com menos de k registros (ex: uma unica pessoa de 80+ no CEP 53000), removemos esses registros. Perder 1 de 32566 e impacto minimo. 
    # Suppression em Python:
group_sizes = df.groupby(["Zip", "Age"]).transform('size')
df = df[group_sizes >= k]  # Remove grupos pequenos
  3. Verificacao em Python A funcao verifica se todo grupo de quasi-identificadores tem pelo menos k registros: 
    def check_k_anonymity(df, k, quasi_identifiers):
    grouped = df.groupby(quasi_identifiers).size()
    return bool((grouped >= k).all())
# Atencao: >= k (nao >= k-1), pois o grupo inclui o proprio registro
Limitacao da k-anonymity: Se todos no grupo de 70-79 em Caen tem Diabetes, a doenca e revelada mesmo com k = 10. Extensoes como l-diversity (valores sensiveis diversificados no grupo) e t-closeness (distribuicao do grupo proxima da global) tentam resolver isso, mas ainda nao oferecem garantias matematicas fortes como a Differential Privacy.

Resposta Aleatoria: o primeiro mecanismo formal de privacidade

O professor pergunta a cada aluno: "Voce colou na prova passada?" Quem colou vai mentir. Como estimar a proporcao real p sem comprometer ninguem?

3.1 Formalizacao

Classe de N alunos. Resposta verdadeira: Xi = 1 (colou) ou 0 (nao colou). Proporcao real: p = (1/N) ∑ Xi (desconhecida).

O mecanismo de Resposta Aleatoria com parametro γ ∈ [0, 1/2]:

Yi = Xi com prob. (1/2 + γ)  |  1 − Xi com prob. (1/2 − γ)
Yi
Resposta dada (observada)
Xi
Verdade (1=colou, 0=nao)
1/2 + γ
Prob. de dizer a verdade
1/2 − γ
Prob. de inverter
γ = 0 P(verdade) = P(inversao) = 1/2. Resposta completamente aleatoria. Privacidade maxima, utilidade zero.
γ = 1/2 P(verdade) = 1, P(inversao) = 0. Resposta exata. Utilidade maxima, privacidade zero.
0 < γ < 1/2 Compromisso: "plausible deniability" — quem responde "sim" pode sempre dizer que o mecanismo inverteu.

3.2 Demonstracoes matematicas

Demonstracao 1: Calculo de E[Yi]

Yi e uma variavel de Bernoulli. Calculamos sua esperanca:

E[Yi] = (1/2 + γ) · Xi + (1/2 − γ) · (1 − Xi)
Pela definicao do mecanismo: com prob. (1/2+γ) respondemos Xi, com prob. (1/2-γ) respondemos 1-Xi.
= Xi/2 + γXi + 1/2 − γ − Xi/2 + γXi
Expandindo os termos: distribuimos cada probabilidade pelo valor correspondente.
= 2γXi + 1/2 − γ
Simplificando: os termos Xi/2 se cancelam, e os dois γXi se somam. Resultado: E[Yi] = 2γXi + 1/2 − γ
Demonstracao 2: Estimador nao-viesado de Xi

Queremos inverter a relacao E[Yi] = 2γXi + 1/2 − γ para recuperar Xi:

E[Yi] − (1/2 − γ) = 2γXi
Subtraimos a constante (1/2 − γ) de ambos os lados.
Xi = (1/2γ) · (E[Yi] − 1/2 + γ) = (1/2γ) · (Yi + γ − 1/2)
Dividimos por 2γ. Definimos o estimador: X̄i = (1/2γ)(Yi + γ − 1/2)
E[X̄i] = (1/2γ)(E[Yi] + γ − 1/2) = (1/2γ)(2γXi) = Xi = E[Xi] ✓
O estimador e nao-viesado! Sua esperanca e exatamente o valor verdadeiro.

Portanto o estimador da proporcao e:

p̂ = (1/N) ∑Ni=1 (1/2γ)(Yi + γ − 1/2)
p̂
Estimativa da proporcao
1/N
Media sobre N alunos
1/(2γ)

E E[p̂] = p (a proporcao real). O estimador e nao-viesado para a media tambem! 👏
Demonstracao 3: Variancia do estimador
V[p̂] = V[(1/N) ∑ (1/2γ)(Yi + γ − 1/2)]
Pela definicao do estimador.
= (1/4N²γ²) ∑ V[Yi]
A constante (1/2γ) sai ao quadrado, e os Yi sao independentes (cada aluno faz seu proprio coin flip).
Yi segue Bernoulli ⇒ V[Yi] = p(1-p) ≤ 1/4
A variancia de uma Bernoulli e maximizada em p = 1/2, onde V = 1/4.
V[p̂] ≤ 1 / (16 · N · γ²)
N
Mais pessoas = menor variancia
γ²
Mais verdade = menor variancia
γ → 0
Variancia → ∞ (explode!)
Conclusao chave: A variancia decresce com N (mais pessoas = melhor estimativa) e com γ² (mais verdade = menos variancia). Quando γ → 0, a variancia explode (→ ∞).

Differential Privacy: o framework matematico

4.1 Motivacao: vulnerabilidade de queries repetidas

Imagine um banco de dados com campos name e salary, acessivel apenas via a query COUNT(*) WHERE <cond>. Mesmo sem acesso direto ao salario, um atacante pode:

-- Busca binaria: testar limiares ate achar o salario exato
COUNT(*) WHERE name="Alice" AND salary < 100000  → 1
COUNT(*) WHERE name="Alice" AND salary < 50000   → 0
COUNT(*) WHERE name="Alice" AND salary < 75000   → 1
-- ... converge para o salario exato de Alice! [9]
Problema fundamental: Se um atacante pode fazer queries infinitas a um mecanismo com ruido de media zero, ele calcula a media das respostas ruidosas e, pela lei dos grandes numeros, o ruido se cancela, revelando o valor real. Por isso DP exige limitar o numero de queries ou usar um privacy budget que se degrada (composicao).

Perspectiva ML: modelos que vazam informacao

Se treinarmos um modelo fθ em X, e depois em X' (que difere em um ponto), e θ muda significativamente, um adversario pode inferir qual ponto mudou. Solucao: adicionar ruido ao treino: θprivate = θ + ruido.

4.2 Definicao formal de ε-DP

Definicao: ε-Differential Privacy

Ingredientes:

Dataset X = (x1, ..., xn)
Mecanismo M : X ↦ Y tal que M(x) = φ(x, U) onde φ e deterministico e U uma semente aleatoria
Datasets vizinhos: X, X' tais que d(X, X') = 1 (diferem em exatamente 1 registro)
Dois datasets sao "vizinhos" se sao identicos exceto por uma unica pessoa.

Definicao: M e ε-DP para ε ≥ 0 se e somente se:

P(M(X) ∈ S) ≤ eε · P(M(X') ∈ S)    ∀ X,X' vizinhos, ∀ S ⊂ Y
A probabilidade de qualquer resultado e quase a mesma, independente de qual dos dois datasets vizinhos foi usado.
Interpretacao: a forma log-ratio

Tomando o logaritmo da definicao:

P(M(X) ∈ S) ≤ eε · P(M(X') ∈ S)
log(P(M(X) ∈ S)) ≤ ε + log(P(M(X') ∈ S))
−ε ≤ log(P(M(X) ∈ S) / P(M(X') ∈ S)) ≤ ε
O log-ratio das probabilidades e bornado por ε em ambos os sentidos. Um adversario vendo a saida de M nao consegue distinguir X de X' alem do fator eε.

Interpretacao dos extremos:

ε → 0: e0 = 1 ⇒ P(M(X)) ≈ P(M(X')). Indistinguiveis! Privacidade maxima.
ε >> 1: eε e grande ⇒ probabilidades podem divergir muito. Privacidade fraca.
Resumo: ε pequeno = muita privacidade, pouca utilidade. ε grande = pouca privacidade, muita utilidade. E o tradeoff fundamental.

4.3 O Mecanismo de Laplace

Para tornar qualquer funcao deterministica f ε-DP, basta adicionar ruido Laplaciano:

M(X) = f(X) + Laplace(0, b)   onde   b = Δf / ε
Conceitos-chave explicados

Sensibilidade Δf: O quanto f pode mudar quando trocamos UM registro:

Δf = maxX,X' vizinhos |f(X) − f(X')|
Exemplo: para COUNT(*), trocar 1 pessoa muda o resultado em no maximo 1. Entao Δf = 1.
Exemplo: para MEAN(salary), se salarios vao de 0 a 200K e temos N pessoas, Δf = 200000/N.

Distribuicao de Laplace:

laplace(x | b) = (1/2b) · exp(−|x|/b)
Uma distribuicao simetrica centrada em 0 com "caudas pesadas". O parametro b (escala) controla a largura: b maior = mais ruido = mais privacidade.

Por que funciona: b = Δf/ε garante que o ruido e grande o suficiente para "esconder" qualquer mudanca de 1 registro. Quanto mais f varia (Δf grande) ou quanto mais privacidade queremos (ε pequeno), mais ruido adicionamos.

# Implementacao em Python:
def differentially_private_output(query_output, epsilon, sensitivity):
    scale = sensitivity / epsilon
    return query_output + np.random.laplace(loc=0, scale=scale)

# Exemplo: count query (sensibilidade = 1)
real_count = len(df[df['Target'] == '<=50K'])
dp_count = differentially_private_output(real_count, epsilon=1, sensitivity=1)

Differential Privacy para Deep Learning: DP-SGD

5.1 Contexto: regressao logistica e gradient descent

No TP, treinamos um classificador logistico fθ que prediz y ∈ {0,1} a partir de x ∈ Rd:

fθ(x) = σ(∑ wi · xi)   onde   σ(z) = 1/(1 + e−z)
fθ
Modelo (prediz P(y=1|x))
x
Entrada (features)
σ (sigmoid)
Comprime para [0,1]
∑ wixi
Produto escalar pesos·features
Por que fθ(x) representa uma probabilidade?

O modelo de regressao logistica calcula:

fθ(x) = σ(∑ wi · xi)
Primeiro, o produto escalar ∑ wi · xi = w1x1 + w2x2 + ... + wdxd produz um numero real z ∈ (−∞, +∞). Esse valor pode ser qualquer coisa — positivo, negativo, enorme.
σ(z) = 1 / (1 + e−z)     σ : ℝ → (0, 1)
A sigmoid σ "comprime" esse valor real para o intervalo (0, 1). Isso e crucial: como a saida esta entre 0 e 1, podemos interpreta-la como uma probabilidade!

Entao definimos:

fθ(x) = Pθ(y = 1 | x)
fθ(x)
Saida do modelo (entre 0 e 1)
Pθ(y=1|x)
Probabilidade de pertencer a classe 1, dado x
Como interpretar: Se fθ(x) = 0.85, o modelo diz "85% de chance de y=1". Se fθ(x) = 0.12, diz "12% de chance de y=1" (ou seja, 88% de chance de y=0).

Os tres comportamentos-chave da sigmoid:

Se ∑ wixi >> 0  ⇒  σ → 1  ⇒  P(y=1|x) ≈ 1
Produto escalar grande e positivo: o modelo esta confiante de que y=1.
Se ∑ wixi << 0  ⇒  σ → 0  ⇒  P(y=1|x) ≈ 0
Produto escalar grande e negativo: o modelo esta confiante de que y=0.
Se ∑ wixi ≈ 0  ⇒  σ ≈ 0.5  ⇒  P(y=1|x) ≈ 50%
Produto escalar perto de zero: o modelo esta indeciso, probabilidade de cara ou coroa.

Para classificar: Usamos o limiar 0.5. Se fθ(x) > 0.5, predizemos y=1; senao, y=0. Os pesos w1,...,wd sao os parametros θ que aprendemos durante o treino, ajustando-os para que o produto escalar tenha o mesmo sinal que o label y que queremos prever.

Para treinar θ, minimizamos a binary cross-entropy loss:

Loss function e gradiente
loss(fθ(xi), yi) = −yi log(fθ(xi)) − (1−yi) log(1−fθ(xi))
Se yi=1: loss = −log(fθ(xi)). Minimizar ⇒ fθ → 1 (predizer y=1 corretamente).
Se yi=0: loss = −log(1−fθ(xi)). Minimizar ⇒ fθ → 0 (predizer y=0 corretamente).

Gradiente (o que usamos para atualizar θ):

∇θ loss = xi · (fθ(xi) − yi)
Se a predicao esta longe do alvo, o gradiente e grande ⇒ θ muda muito. Se esta perto, o gradiente e pequeno.

Gradient Descent: a cada iteracao, calculamos o gradiente medio sobre todo o dataset e atualizamos:

θt+1 = θt − α · (1/N) ∑i ∇θ loss(fθ(xi), yi)
α e o learning rate. Repetimos ate convergencia.
# Gradient descent basico (do TP):
def gradient_descent(iterations, lr, X_train, y_train):
    theta = initialise_params()
    for it in range(iterations):
        grads = np.array([gradient(theta, X_train[i], y_train[i]) 
                          for i in range(X_train.shape[0])])
        average_gradient = np.mean(grads, axis=0)
        theta = theta - lr * average_gradient
    return theta

5.2 DP-SGD: clip, ruido e algoritmo

Para tornar o gradient descent ε-DP, adicionamos dois ingredientes: gradient clipping e ruido Laplaciano.

Passo 1: Gradient Clipping

Problema: sem clipping, um unico outlier pode dominar o gradiente ⇒ vazamento de informacao.

clip(g, K) = g · min(1, K / ||g||2)
Se ||g|| ≤ K: mantem o gradiente intacto (min(1, K/||g||) = 1).
Se ||g|| > K: escala o gradiente para ter norma exatamente K (min(1, K/||g||) = K/||g|| < 1).

Efeito: Apos o clipping, todo gradiente individual tem ||g̃i|| ≤ K. Isso borna a influencia maxima de qualquer amostra: a sensibilidade do gradiente medio e Δ = K/N.

Passo 2: Adicionar ruido calibrado
sensibilidade = K / N (influencia maxima de 1 amostra no gradiente medio)
ruido = Laplace(0, sensibilidade/ε) por dimensao de θ
θt+1 = θt − α · ((1/N) ∑ clip(gi, K) + ruido)
O ruido e proporcional a K (mais clipping = mais ruido) e inversamente proporcional a ε (mais privacidade = mais ruido).
# Implementacao completa (do TP):
def clip_gradient(grad, threshold):
    norm = np.linalg.norm(grad)
    if norm > threshold:
        grad = grad * (threshold / norm)
    return grad

def epsilon_dp_gradient_descent(iterations, lr, epsilon, threshold, X_train, y_train):
    theta = initialise_params()
    n = X_train.shape[0]
    for it in range(iterations):
        grads = np.array([gradient(theta, X_train[i], y_train[i]) for i in range(n)])
        clipped = np.array([clip_gradient(g, threshold) for g in grads])
        avg_grad = np.mean(clipped, axis=0)
        sensitivity = threshold / n
        noise = np.random.laplace(0, sensitivity/epsilon, size=theta.shape)
        theta = theta - lr * (avg_grad + noise)
    return theta

5.3 O tradeoff ε vs accuracy

Experiencia do TP: Testando diferentes valores de ε com 30 iteracoes e threshold=1:
ε = 0.01~50% accuracy (aleatorio). Muito ruido, modelo nao aprende nada.
ε = 0.1 - 160-70% accuracy. Privacidade forte, utilidade moderada.
ε = 5 - 1075-80% accuracy. Privacidade fraca, se aproxima do nao-privado.
ε = 100+~83% (quase igual ao baseline sem DP). Ruido desprezivel.

Resumo e questoes para reflexao

  1. Privacidade e um tema serio e em evolucao GDPR, European AI Act — os direitos e deveres estao cada vez mais definidos. Empresas que ignoram privacidade correm riscos juridicos e reputacionais.
  2. Protecoes ingenuas falham De-anonimizacao, ataques de linkage, hashing reversivel, memorizacao de modelos — cada "solucao" simples foi contornada. Privacidade requer frameworks matematicos.
  3. Differential Privacy e o framework rigoroso Usa ruido calibrado (Laplace) para esconder informacoes individuais enquanto preserva tendencias globais. O parametro ε quantifica o tradeoff.
  4. DP-SGD aplica DP a deep learning Gradient clipping (bornar a influencia de cada amostra) + ruido Laplaciano nos gradientes. O custo e uma reducao na precisao proporcional a 1/ε.
  5. O tradeoff e universal γ na Resposta Aleatoria, ε no DP, K/ε no DP-SGD — todos expressam o mesmo compromisso: privacidade vs utilidade. Mais dados (N grande) permitem mais ruido sem perder utilidade.
